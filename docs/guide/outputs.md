# Outputs

Besides the [tree](tree.md), svhier writes two kinds of data. Each one goes
to a file, or to stdout when you leave out the file name.

::::{tab-set}
:::{tab-item} Filelist
```bash
svhier -r rtl/ --filelist compile.f
```
:::
:::{tab-item} YAML
```bash
svhier -r rtl/ --yaml hierarchy.yaml
```
:::
:::{tab-item} Piped
```bash
svhier -r rtl/ --yaml | yq '.files[].defs[].mod_name'
```
:::
::::

(filelist-output)=
## Filelist

A plain-text filelist with sources in **dependency order** (definitions
before their users), ready to pass to a simulator or synthesis tool with
`-f`:

```text
// Generated by svhier — files in compilation order
+incdir+rtl/include
+define+SYNTHESIS
rtl/alu_pkg.sv
rtl/adder.sv
rtl/mux2.sv
rtl/alu.sv
```

- **Ordering** follows module instantiation, package imports, `pkg::name`
  references, and interface ports and instances.
- **`+incdir+`** lines cover `-I` directories, every directory that contains
  `.svh`/`.vh` headers, every directory an `` `include `` was actually
  resolved from, and include dirs found through [`-y`](libdirs.md).
- **`+define+`** lines repeat the macros given with `-D` or `+define+` in
  command files.
- **With `--top`**, only the files the tops need are listed. slang's
  dependency trimming decides this; it follows module, interface, package
  and class references.
- **Duplicates.** If a name is {ref}`defined more than once <duplicates>`,
  dependencies resolve to the copy slang uses.
- **Library files** pulled in with `-y` are included.

The format works with VCS, Questa and Xcelium.

:::{tip}
If the files depend on each other in a cycle, svhier falls back to the input
order instead of failing.
:::

## YAML

The full hierarchy as data: one entry per file, with the modules defined in
it, their package imports and their direct child instances.

```yaml
files:
- file_name: rtl/alu.sv
  defs:
  - mod_name: alu
    pkg_imports:
    - alu_pkg
    insts:
    - mod_name: adder
      inst_name: u_add
    - mod_name: mux2
      inst_name: u_mux
- file_name: rtl/adder.sv
  defs:
  - mod_name: adder
    insts: []
```

- `pkg_imports` is omitted when a module imports nothing.
- `inst_name` is the instance path relative to the parent module, e.g.
  `g_loop[0].u_core`.
- `insts` can contain modules that have no definition
  ([blackboxes](missing.md)).
- Modules that are never instantiated still appear in `defs`.
