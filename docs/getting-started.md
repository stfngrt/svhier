# Getting started

This walkthrough takes the [CVA6](https://github.com/openhwgroup/cva6) RISC-V
core from "a pile of 300 `.sv` files" to a complete hierarchy and a filelist
you can compile, in four commands.

```bash
git clone --recursive https://github.com/openhwgroup/cva6
cd cva6
```

## 1. Look at the tree

Point svhier at the RTL and tell it which module is the top. `-r` searches
directories recursively. `-x` skips any path containing that name, here the
testbenches.

```bash
svhier -r core -x test -x tb --top cva6
```

```text
cva6
├── i_frontend (frontend)
│   ├── i_instr_realign (instr_realign)
│   ├── ras_gen.i_ras (ras)
│   ├── bht_gen.i_bht (bht)
│   ├── gen_instr_scan[0].i_instr_scan (instr_scan)
│   ├── gen_instr_scan[1].i_instr_scan (instr_scan)
│   └── i_instr_queue (instr_queue)
…
├── instr_tracer_i (instr_tracer) (blackbox)
…
```

Generate blocks and instance arrays are elaborated, so each instance shows
its real path (`gen_instr_scan[1].i_instr_scan`). Note the `(blackbox)`
marker: something is missing.

:::{tip}
Leave out `--top` to get one tree for every module that nothing else
instantiates. That's a quick way to spot dead code and stray testbenches.
:::

## 2. See what's missing

The **Not found** table on stderr lists everything slang couldn't resolve:

```text
                               Not found
┏━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃ Kind            ┃ Name                 ┃ Referenced in              ┃
┡━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━━━━━━━━━━┩
│ blackbox module │ sram_cache           │ cva6_icache.sv             │
│ blackbox module │ instr_tracer         │ cva6.sv                    │
│ blackbox module │ pulp_clock_gating    │ clock_divider.sv (+2 more) │
│ blackbox module │ cluster_clock_gating │ generic_fifo.sv (+1 more)  │
│ package         │ axi_pkg              │ cva6.sv                    │
│ …               │                      │                            │

```

Rather than hundreds of raw compiler errors, you get the short list of
things to go and find. Most errors on an incomplete file set are follow-on
errors from exactly these.

## 3. Let svhier find them

The missing pieces live in CVA6's `common/` and `vendor/` directories.
Compiling those whole would drag in hundreds of unrelated files, so pass
them as **library directories** instead:

```bash
svhier -r core -y common -y vendor -x test -x tb --top cva6
```

```text
                          Pulled in from -y
┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┳━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃ Name                         ┃ From                                                                      ┃
┡━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━╇━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┩
│ sram_cache                   │ common/local/util/sram_cache.sv                                           │
│ instr_tracer                 │ common/local/util/instr_tracer.sv                                         │
│ pulp_clock_gating            │ vendor/pulp-platform/tech_cells_generic/src/deprecated/pulp_clk_cells.sv  │
│ axi_pkg                      │ vendor/pulp-platform/axi/src/axi_pkg.sv                                   │
│ tc_sram_wrapper_cache_techno │ common/local/util/tc_sram_wrapper_cache_techno.sv                         │
│ tc_clk_gating                │ vendor/pulp-platform/tech_cells_generic/src/rtl/tc_clk.sv (+1 other …)    │
│ tc_sram                      │ vendor/pulp-platform/tech_cells_generic/src/rtl/tc_sram.sv (+1 other …)   │
│ …                            │                                                                           │
└──────────────────────────────┴───────────────────────────────────────────────────────────────────────────┘
```

svhier pulled in the missing files over a few rounds. `sram_cache` needed
`tc_sram_wrapper_cache_techno`, which needed `tc_sram`, and so on. The
**Not found** table is gone and so are the blackboxes.

A **Defined more than once** table also appears. CVA6 ships one
`cva6_config_pkg` per target, and a real build compiles exactly one of them.

:::{tip}
CVA6 has a project filelist that picks one target. Pass it with `-f` to get a
clean, duplicate-free build (see {ref}`command-files`):

```bash
export CVA6_REPO_DIR=$PWD HPDCACHE_DIR=$PWD/core/cache_subsystem/hpdcache TARGET_CFG=cv64a6_imafdc_sv39
svhier -f core/Flist.cva6 --top cva6
```
:::

## 4. Export

Write a filelist in compilation order, ready for your simulator:

```bash
svhier -r core -y common -y vendor -x test -x tb --top cva6 --filelist cva6.f
```

```text
// Generated by svhier — files in compilation order
+incdir+core/cache_subsystem/hpdcache/rtl/include
+incdir+core/include
…
core/cache_subsystem/hpdcache/rtl/src/common/hpdcache_1hot_to_binary.sv
core/cache_subsystem/hpdcache/rtl/src/common/hpdcache_decoder.sv
…
```

Or get the full hierarchy as data with `--yaml hierarchy.yaml`.
