# Usage

## Installation

```bash
pip install svhier
```

Or, if you are working from source with [uv](https://docs.astral.sh/uv/):

```bash
uv sync
```

## Quick start

Parse a single file and print the hierarchy to stdout:

```bash
svhier top.sv --yaml
```

Parse an entire directory recursively and write both outputs to files:

```bash
svhier -r rtl/ --yaml hierarchy.yaml --filelist compile.f
```

Use a project filelist instead of scanning directories, and pick the top module:

```bash
export CVA6_REPO_DIR=$PWD/cva6 HPDCACHE_DIR=$PWD/cva6/core/cache_subsystem/hpdcache TARGET_CFG=cv64a6_imafdc_sv39
svhier -f $CVA6_REPO_DIR/core/Flist.cva6 --top cva6 --yaml hier.yaml --filelist cva6.f
```

Command files may use `+incdir+`, `+define+`, nested `-f`/`-F` and `${VAR}`
environment variables.  `-F FILE` resolves the paths inside FILE relative to FILE;
`-f` resolves them relative to the working directory.  `-I DIR` and `-D NAME[=VALUE]`
add include directories and macros, and can be combined with paths and command files.

`--top MODULE` (repeatable) elaborates only the given tops, which keeps testbenches and
unused variants out of the hierarchy, and limits the filelist to the files the tops need.

:::{note}
All diagnostic output (spinner, summary table, warnings, errors) goes to
**stderr** so that `--yaml` and `--filelist` stdout output can be piped
safely.
:::

## YAML output

The `--yaml` output describes the module/instance hierarchy of every parsed
file.  Each file entry lists the modules defined there together with their
direct child instances and package imports.

```yaml
files:
- file_name: rtl/alu.sv
  defs:
  - mod_name: alu
    insts:
    - mod_name: adder
      inst_name: u_add
    - mod_name: mux2
      inst_name: u_mux
- file_name: rtl/adder.sv
  defs:
  - mod_name: adder
- file_name: rtl/mux2.sv
  defs:
  - mod_name: mux2
```

:::{note}
Modules that are defined but never instantiated still appear in `defs` with
an empty `insts` list.
:::

Package imports are shown when present:

```yaml
- mod_name: alu
  pkg_imports:
  - alu_pkg
  insts: []
```

## Filelist output

The `--filelist` output is a plain text file listing source files in
dependency order (dependencies before dependants), ready to pass to a
simulator or synthesis tool.

```text
// Generated by svhier — files in compilation order
+incdir+rtl/include
rtl/adder.sv
rtl/mux2.sv
rtl/alu.sv
```

`+incdir+` lines are emitted for `-I` directories, for any directory that contains
`.svh`/`.vh` header files, and for every directory an `` `include`` was actually
resolved from.  `+define+` lines repeat the macros given by `-D` or command files.
The format is compatible with VCS, Questa, and Xcelium.

:::{note}
If a module, interface or package name is defined in more than one file, svhier
prints a warning naming the copy slang uses; dependencies resolve to that copy.
:::

:::{tip}
If a dependency cycle is detected, svhier falls back to the original input
order and continues without error.
:::

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Elaboration completed with no errors |
| `1` | pyslang reported one or more error-level diagnostics |
